vacancy-check

Проверка вакансий региона 39 (Калининградская область) на прозрачность: понятно ли соискателю, что за работа, сколько платят, когда и где работать. Данные берутся из открытого API «Работа России», результат сохраняется в JSON-отчёт. Сделано для отборочного задания КАНТКОД, «Прозрачная вакансия».


КАК ЭТО РАБОТАЕТ

1. Вакансии загружаются из API (параметр --url) или из локального файла (--file) в формате ответа API.
2. Каждая вакансия приводится к единому виду: разные поля вроде requirements и requirement.qualification собираются в один набор.
3. Правила без ИИ ловят то, что видно однозначно: оплата не указана нигде, минимум больше максимума, не указан тип занятости или график, адрес только на уровне региона, служебный код в названии, опыт «0 лет» при тексте «не менее 5 лет».
4. Шаг с ИИ: модель просматривает семь тем (название, обязанности, требования, оплата, график, место работы, тип занятости) и ищет расплывчатые формулировки и противоречия между полями.
5. Ответ модели проверяется кодом. Цитата должна дословно встречаться в вакансии, иначе замечание отбрасывается. Туда же отбрасываются замечания по неизвестным темам, одно слово вместо объяснения, дубли и жалобы на «отсутствие» сведений, которые в вакансии есть.
6. Отчёт сначала пишется во временный файл и только потом подменяет старый, поэтому недописанного отчёта не бывает.


ГДЕ ИСПОЛЬЗУЕТСЯ ИИ

Только на шаге 4. Провайдер по умолчанию: GigaChat (модель GigaChat-2-Max), доступ по персональному бесплатному ключу физического лица. Ответ запрашивается по строгой JSON-схеме. Всё остальное, включая правила и проверку ответа модели, обычный код.


УСТАНОВКА

Нужен Python 3.11 или новее.

    pip install -r requirements.txt


НАСТРОЙКИ

Настройки лежат в config.toml: адрес API, размер страницы, лимит вакансий, путь к отчёту, режим ИИ, путь к кешу. Любой параметр можно переопределить флагом командной строки.

Ключи в репозиторий не кладутся. Их читают из переменных окружения или из файла .env (он в .gitignore). Шаблон лежит в .env.example.

Переменные:
GIGACHAT_CREDENTIALS: ключ авторизации GigaChat (строка для заголовка Basic).
GIGACHAT_SCOPE: область доступа, по умолчанию GIGACHAT_API_PERS.
GIGACHAT_CA_BUNDLE: путь к корневому сертификату Минцифры.
LLM_API_KEY, LLM_BASE_URL, LLM_MODEL: любой сервис с API в формате OpenAI.

Сертификат Минцифры нужен, потому что серверы Сбера подписаны им, а в стандартных хранилищах он обычно не лежит: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt


ЗАПУСК

Точка входа: python -m vacancy_check. На Windows может понадобиться py -m vacancy_check.

Обработка начинается с файла vacancy_check/__main__.py, который вызывает vacancy_check/cli.py. По расписанию то же самое делает workflow .github/workflows/analyze.yml.

Проверочный режим на учебном наборе организаторов, без доступа к сети и без ключей:

    python -m vacancy_check --file examples/sample_vacancies.json --ai replay --cache examples/ai_recording.json --out reports/check.json

Живой запуск по API региона с GigaChat:

    python -m vacancy_check --ai gigachat --out reports/latest.json

Без ИИ, только правила:

    python -m vacancy_check --ai none

Коды завершения: 0 успех, 1 не удалось получить вакансии (прежний отчёт остаётся на месте), 2 не настроен ИИ.


КЛЮЧ ДЛЯ ИИ: КАК СОЗДАТЬ И ИСПОЛЬЗОВАТЬ

В репозитории ключа нет и не будет. Для запуска режима с ИИ нужен свой бесплатный ключ GigaChat. Покупать ничего не нужно, ключ для физических лиц выдаётся бесплатно, нужна только регистрация в кабинете Сбера.

Как создать ключ.
1. Зарегистрироваться или войти на https://developers.sber.ru/studio. Бесплатные токены для физических лиц выдаются именно там, коммерческий доступ через Cloud.ru нам не нужен.
2. Создать проект с API GigaChat.
3. В проекте открыть раздел «Настройка API». В блоке «Данные для авторизации запросов к API» указаны Client ID и Scope. Нужное значение Scope: GIGACHAT_API_PERS.
4. В блоке «Ключ авторизации» нажать «Получить новый ключ». Authorization key показывается один раз, его нужно сразу скопировать и сохранить. Именно он, а не Client ID, подставляется в GIGACHAT_CREDENTIALS.

Как подготовить запуск.
5. Скачать корневой сертификат Минцифры по ссылке выше и сохранить как russian_ca.pem в папке проекта. Без него соединение с серверами Сбера не проходит проверку.
6. Скопировать файл .env.example в .env и заполнить две строки:

    GIGACHAT_CREDENTIALS=вставьте_ключ
    GIGACHAT_CA_BUNDLE=russian_ca.pem

Файл .env находится в .gitignore и в репозиторий не попадает. Вместо файла можно задать те же переменные в окружении. В Windows PowerShell:

    $env:GIGACHAT_CREDENTIALS="вставьте_ключ"
    $env:GIGACHAT_CA_BUNDLE="russian_ca.pem"

В Linux и macOS:

    export GIGACHAT_CREDENTIALS="вставьте_ключ"
    export GIGACHAT_CA_BUNDLE="russian_ca.pem"

Как запустить проверку с ИИ на своём наборе вакансий:

    python -m vacancy_check --file путь/к/вакансиям.json --ai gigachat --out reports/check.json

То же самое делается в окне: python -m vacancy_check.gui, режим «GigaChat». Ключ окно берёт из .env.

Модель недетерминирована, поэтому на учебном наборе замечания могут немного отличаться от examples/report.sample.json.

Запасные варианты.

Воспроизведение записи, ключ не нужен. Команда проверочного режима выше. Ответы берутся из examples/ai_recording.json, мы записали их живым прогоном GigaChat на учебном наборе. Работает только на учебном наборе: запись привязана к тексту вакансий, и на другом файле ответов модели не найдётся. Тогда ID таких вакансий попадут в ai.failed, а замечания правил останутся.

Другая модель с OpenAI-совместимым API. Задать LLM_API_KEY, LLM_BASE_URL, LLM_MODEL и запустить с --ai openai. Этот вариант в коде есть, но на реальном сервисе мы его не проверяли.

Если жюри нужен другой способ запуска режима с ИИ, мы готовы реализовать любой из следующих:
1. Локальная ИИ-модель.
2. Поднять сервер.


ФОРМАТ ОТЧЁТА

    {
      "generated_at": "2026-11-24T20:09:32+00:00",
      "source": "examples/sample_vacancies.json",
      "ai": {"enabled": true, "provider": "gigachat", "model": "GigaChat-2-Max", "failed": []},
      "vacancies": [
        {
          "id": "DEMO-39-004",
          "url": null,
          "issues": [
            {
              "topic": "место работы",
              "field": "duty",
              "quote": "Работа полностью дистанционная из любого города.",
              "problem": "что именно непонятно соискателю",
              "recommendation": "что уточнить у работодателя",
              "origin": "llm",
              "conflicts_with": {"field": "requirement.qualification", "quote": "вторая цитата"}
            }
          ]
        }
      ]
    }

На каждую вакансию ровно один результат. Поле origin показывает, кто нашёл замечание: rule или llm. Поле conflicts_with есть только у противоречий. Если ИИ не ответил по какой-то вакансии, её ID попадает в ai.failed, а замечания правил остаются. Пример на учебных данных: examples/report.sample.json.


ОКНО С ИНТЕРФЕЙСОМ

    python -m vacancy_check.gui

На Windows py -m vacancy_check.gui. Окно умеет то же, что командная строка: выбрать файл с вакансиями или взять API региона 39, выбрать режим ИИ (GigaChat, записанные ответы или только правила), задать максимум вакансий и нажать «Создать отчёт». Готовый отчёт сохраняется в папке reports и сразу показывается в окне: цитаты, рекомендации, поиск, фильтры по теме и источнику замечания. Ранее сохранённый отчёт открывается кнопкой «Открыть готовый отчёт». Ключ окно берёт из .env, как и командная строка.

Окно написано на tkinter, он входит в состав Python на Windows и macOS. На Linux может понадобиться пакет python3-tk.


АВТОМАТИЧЕСКИЙ ЗАПУСК

Файл .github/workflows/analyze.yml: запуск каждый день в 05:00 UTC и вручную через workflow_dispatch. Отчёт сохраняется как артефакт vacancy-report. Ключ берётся из секрета репозитория GIGACHAT_CREDENTIALS. Если секрета нет, воркфлоу работает без ИИ.


ТЕСТЫ

    pip install -r requirements.txt
    python -m pytest -q

Тесты не ходят в сеть и не требуют ключей.


ОГРАНИЧЕНИЯ

Как именно API трактует offset, страницами или записями, мы не знаем точно. Загрузчик определяет это сам по доле повторов, но на всём объёме региона не проверялся.

Серверы GitHub находятся за рубежом, поэтому доступность trudvsem.ru и серверов Сбера из Actions не проверена. Если запуск не пройдёт, то же расписание можно поставить на любом сервере в России командой из раздела «Запуск».

Результат живого запуска зависит от модели и может меняться от прогона к прогону. Правила без ИИ детерминированы.

Модель смотрит на текст вакансии и не знает, правдиво ли он описывает реальные условия.
